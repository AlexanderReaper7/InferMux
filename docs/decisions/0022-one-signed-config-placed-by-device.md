## Context

On 2026-10-10 the user could not disable the CPU embedder and called the load balancing illegible. Turning off that one route meant editing up to five places: the `llama-embed` unit in nixcfg's `llm.nix` (a rebuild), the `embed-cpu` peer in `models/embed-cpu.yaml`, the third place in `failover.yaml` (which the zbox reads through a symlink, so only after a push and its pull timer), and a hand-written unit described below. The UI showed none of the routing. It never read `failover.yaml`, peers were a textarea, and each host's UI listed only its own models. `failover.yaml` named its places three ways: `zbox`, `strix`, `strix/embed-cpu/Octen-Embedding-4B.Q8_0`.

A separate fault made it worse. `/etc/systemd/system.control/llama-embed.service`, written 2026-10-08 01:39 with its own `multi-user.target.wants` link, shadowed the Nix unit (`FragmentPath` pointed at it). No change in `llm.nix` could stop the embedder, and the 2026-10-09 `cpu-inference.slice` fix never applied: the running embedder was in `system.slice` at nice 0.

The agent offered three options: a page over `failover.yaml`; that page plus InferMux running the CPU server; or one config from which every host's models and routing are derived. The user chose the last and described it. There is one InferMux per computer. Each has several devices, such as one GPU and one CPU, and a device runs whichever runtime a model needs, mainline llama.cpp or a fork. Balancing decides where a model runs normally, and failover keeps some service when a host or device goes down. The user adds models or model groups to the config: the embedder on the GPU and the CPU, a 7B chat model on the GPU only. The same file goes to every host, each host reads its own part, and a change applies at runtime.

## Decision

The user's choices, 2026-10-10:

1. **One config, the same on every host, and each host runs its own part.** A host has devices; a model is placed on devices.
2. **Two lanes per model, `balance` and `failover`.** Balance is the normal places, in order, each up to its limit, as 0019's overflow works today. Failover places are used only when every balance place is down or refusing, not when one is merely busy. Rejected: a failover rule per host or device ("zbox/gpu's models move to strix/gpu"); two separate files.
3. **A model group is a placement label.** Placing a group places every member. Clients still ask for a model by name. Rejected: a group as a name clients ask for, which changes the API; no groups.
4. **The daemons push the config to each other, with a revision.** Each daemon keeps its copy under its state directory, not in the checkout, because the zbox's `nixcfg-pull` stops on an uncommitted change and a pushed file would be one. The UI writes a copy to nixcfg for history, committed with Commit as now. Rejected: git as the transport, which means the UI pushes (reversing 0005), the passphrase on every change, and no change while GitHub is down.
5. **A model is defined once.** The device adds its own selection, and a placement may override a flag, such as a smaller `--ctx-size` on the 1060. Rejected: a full command per device.
6. **Two hosts edited apart: the last write wins, with a warning and a backup.** The later signed timestamp wins, ties broken by host name. The losing version is kept on both hosts, and both UIs show it as a diff with a warning until the user dismisses it. Rejected: holding both versions until the user picks; refusing changes while any host is unreachable, which takes away the reason the zbox has its own UI (0008).
7. **Each device runs one model or several at once, as a setting on the device.** The GPUs swap one at a time as now; the CPU, with 96 GB, can keep several running. A device that swaps may keep a group of models loaded together, its `together` ([0029](0029-a-group-stays-loaded-together-on-a-device-that-swaps.md)). This is llama-swap's matrix router, so no upstream file changes. Rejected: a memory budget per device, which needs reliable sizes per model and context; one model at a time everywhere.
8. **A host fetches a missing GGUF from another host that has it, or from its source** (Hugging Face, 0012), and skips that placement until the file is complete. Rejected: refusing the change until the file is there.
9. **A YAML editor, not drag and drop.** The user asked for an editor with help built in: completion and hover docs from a schema generated from the Go config types (device names, model names, runtimes, GGUF paths included); validation as you type by the loader the daemons run; commands that add a model from an unused GGUF or a Hugging Face repo, with flags copied from a model on the same runtime. The editor replaces the model form, the Peers textarea and the Routing textarea. The KV-kernel warning becomes a diagnostic on the cache-type line. Rejected: keeping the form beside the editor, two editors writing one file.
10. **The config is signed with a dedicated key, and verification is forced.** An ed25519 key used for nothing else. Every daemon checks the signature against public keys from Nix (`services.infermux`), never from the config, since a config that names its own trusted key proves nothing. A daemon never applies a config that fails the check. It keeps running the last one that passed, and a new host with none runs no local model until a signed one arrives. The host key gains no power: it reads the other host's model list and carries a signed config, and cannot write one. Rejected: the user's GPG key, where a leak of either the config or the commit key would give both; each host's own key, which lets a compromised host rewrite every host.

The file's variables reach the child on stdin with the part, and the child sets them once the Go runtime has started, so the runtime reads none of them as a setting. No stand-in in child env.", after the agent found that the child had read its environment's `GOMAXPROCS` at start: the stand-in `735700357` (below), there when the part read `${env.GOMAXPROCS}`, made it grow to 58.5 GB in 10 s. So a `GOMEMLIMIT` the runtime would refuse at start passes the check, and the daemon, whose runtime reads the file at start, still refuses it. An argument and not a variable makes it the loader, and the loader is chosen before the passphrase command, so no variable the file sets changes what the child runs: sol's review 15 had `INFERMUX_UI_GPG` in the file pass a check that should fail, and `INFERMUX_UI_LOAD=` hang it. The UI's own environment never holds a key, so neither do git, nix and the passphrase command under it, and a variable of the UI's session does not count as the daemon's. The UI reads the file at each check. The agent's calls in it: the UI reads only the file's blank lines, comments and NAME=VALUE lines whose value is printable ASCII with no quote, backslash or `$` and no space at either end, and refuses the file otherwise. systemd unquotes a quote and a backslash and trims the ends; llama-swap escapes a quote and a backslash, and can expand a `$` as a macro once the value is in the config; and Go's `%q` prints any other byte escaped, which sol's review 15 found with a tab in a key that net/url's error printed as `\t`, past the redaction the check had then. The check's answer now comes from a load that never had the values (below), so that reason is gone. The user kept the rule on 2026-10-15, relayed as "Printable-ASCII rule: opt a. Keep, rewrite reason to one that holds." The agent's reason since: of the other bytes, systemd refuses the whole file for one that is not UTF-8 and trims a tab at either end, so reading them would copy two more of systemd's rules, and no key has such a byte. ## Proposed by the agent, agreed by the user the same day

- **"Device"** for the hardware unit, llama.cpp's own word (`--device`, `CUDA0`). "Resource group" would clash with llama-swap's `groups`.
- **The config is a directory, signed as one unit:** `infermux.yaml` for hosts, devices, clouds, groups, `balance` and `failover`, and `models/<name>.yaml` for each definition, which keeps each model's dated notes in its own file. The signature covers a manifest of the revision, the timestamp, the host that published it, and the SHA-256 of every file.
- **Each model records its GGUF's SHA-256 in the config.** A file fetched from another host is checked against what the user signed. Without it a compromised host could hand llama.cpp's parser a crafted file, which is what forced verification is meant to prevent. The add-model command fills it in from Hugging Face's metadata or by hashing the local file.
- **Another host first, then the source,** for a missing GGUF. The tailnet is closer than Hugging Face, and the hash makes the order safe.
- **Editing is a draft; Publish signs and pushes.** Validation runs on the draft. The private key is age-encrypted with a passphrase (scrypt) in nixcfg, and the UI decrypts it in memory for one Publish. The passphrase is random and lives in the user's login keyring on strix. strix's UI reads it there through `ui.configPassphraseCommand`; the zbox's UI, with no keyring (0008), asks the browser for it. The user, 2026-10-14: "If infermux needs a new key then just make one. Just put it password less onto my keyring." A random passphrase in the keyring, rather than a key with none, is the agents' reading of that: the coordinating agent offered it and the building agent took it, because `infermux-config` refuses an empty passphrase and the key in nixcfg stays encrypted. The cost is that whoever reaches strix's UI can sign a config every host runs. The user kept strix's UI on the tailnet, 2026-10-14: "thats fine. all other users in that tailnet are default blocked. only services tagged with the tag that allows others access are able to access said service." A host without the passphrase still cannot sign (decision 10).
- **A device decides its hardware by environment, not only by flags.** A GPU device sets `CUDA_VISIBLE_DEVICES=<index>` and a CPU device sets it empty and replaces a command's `-ngl` and `--device` with `--device none -ngl 0`, so a stray `-ngl 99` in a model cannot reach a card it was not placed on. This answers 0011's objection to CPU models under InferMux, that a GPU model filed under the CPU by mistake would hide from the warden. The empty variable also covers raw commands such as the reranker and immich-ml.
- **The warden's rules apply per device, not per host.** 0011's three rules (unload on a yield, free VRAM read only with nothing loaded, batch refused in a pause) were why a CPU model could not live under InferMux: they treated every local model as the card's tenant. Per device, a GPU yield unloads and gates only that GPU's models, and the VRAM rule stays a GPU rule. The CPU's own rules are in "The warden covers every device" below; this paragraph, as first written, gave the CPU none.
- **CPU devices run their servers in an idle slice at the root of the cgroup tree,** through `Delegate=` on `infermux.service` or a transient unit. Not `cpu-inference.slice` as nixcfg names it today: systemd reads a dash in a slice name as nesting, so it is `_cpu.slice/cpu-inference.slice`, and its `cpu.idle` ranks it only inside `cpu.slice`, which competes with `user.slice` at weight 100. Measured 2026-10-10 with a busy loop in each, both pinned to core 23 for 10 s: in `cpu-inference.slice` 23% of the core against 76% in `user.slice`; in a slice at the root set to `CPUWeight=idle`, 0% against 98%.
- **What stays as it is:** `warden.yaml`'s per-host policy (desktop and priority processes, ComfyUI, consumers) in the first version; `<host>/<model>` addressing a request to one host; a yielded card dropping out of `balance` (0021); `batch_only` and `only_if_idle` as conditions on a placement.

## The warden and the config

The user asked, 2026-10-10, whether the warden is the host's local rules for what the host must put first so its other tasks keep running, applying only to processes outside InferMux, with InferMux's own work governed by the config. The first half is right, the second the wrong way round, and the split that follows is the one this design keeps.

**The config says where InferMux's work may run. The warden says whether one host's GPU takes it right now.** The warden is local because the machine that measures is the machine that decides (0001). It protects the host's other GPU work, but it acts on InferMux, not on that work. It unloads InferMux's models, refuses and cancels InferMux's batch requests, and pauses InferMux's consumers. A game or OBS is never touched. The one outside process it acts on is an idle ComfyUI, which it frees so the card can be measured as free (0002).

The order on a GPU is: the user's own request, which is never killed even when a game wants the card (0004); then the host's other GPU work; then InferMux's batch work. The warden outranks the config. A yielded GPU device drops out of `balance` (0021), and the config cannot place work on it. The warden's GPU rules never send work anywhere. They only refuse, unload, cancel and pause, and the config's lanes decide where refused work goes next. `stuck.escalate_to` (0015) is the exception, a routing choice that lives in `warden.yaml`; whether it moves into the config is open.

## The warden covers every device

The user, 2026-10-10: the warden should cover the CPU too, so it works for every device InferMux may use. The loop is the same for each device: measure, decide busy or free, act. A busy device drops out of `balance` (0021 for every device), and the warden refuses and cancels batch work on its models. The user's own request is never killed (0004). Each device has its own verdict and its own `resume_quiet_seconds`.

The warden does not replace the idle cgroup. It polls every few seconds, while the scheduler decides every few milliseconds, and the 2026-10-09 desktop lag was a scheduling problem a poll cannot catch. The cgroup decides who gets a core at each instant. The warden decides whether work is sent to the CPU at all.

The user's choices:

1. **A busy CPU routes and refuses, and the warden unloads only when RAM runs short.** An idle CPU model holds RAM and no CPU time, so a yield on CPU load unloads nothing. Under a floor of available RAM the warden unloads the CPU device's models, as on a GPU once interactive traffic is quiet (0004). Rejected: no unload at all; unloading on every CPU yield, which frees RAM nobody asked for and makes the next request pay the load. To measure first: llama.cpp maps the GGUF, and mapped pages are page cache the kernel can reclaim and `MemAvailable` already counts, so an unload frees mostly the KV cache and compute buffers. The floor has to be set against that number.
2. **The CPU is busy when CPU time used outside InferMux's cgroups crosses a threshold for a window, or when a priority process runs.** The kernel charges every nanosecond to a cgroup, so this is exact and readable while models run, unlike free VRAM (0002). Rejected: CPU pressure (PSI) in `user.slice`, which with InferMux idle-weighted mostly fires when the desktop starves itself; both together.
3. **A placement declares every device it occupies.** A model with `--fit` runs the layers that do not fit in VRAM on CPU threads: the 27B has 26 of its 66 layers on the 3080 (`models/README.md`, 2026-08-15). It is placed as occupying the GPU and the CPU, and a busy CPU refuses its batch work too. The editor's validation warns when `--fit`, a low `-ngl` or `--cpu-moe` suggests CPU use the placement does not declare. Rejected: inferring it from the flags, which cannot say how much, since `--fit` splits at load time; counting such a model on its GPU only, which leaves the desktop unprotected from its threads, as today.
4. *Replaced the same day by [0023](0023-a-batch-request-is-a-job-paused-mid-inference.md): first-party consumers send jobs that InferMux pauses and resumes, and nothing is pushed to them. Until a consumer sends jobs, the push goes on, and it carries the CPU's verdict too: a consumer is paused while either device of the host is yielded, which is the second alternative rejected below. On 2026-10-14 the user approved announcing the CPU's verdict, once the 35B was measured on the CPU: 11.7 of strix's 24 threads busy while it answered, 19.2 GiB of its GGUF resident in RAM and 5.5 GiB in VRAM. The agent built it as that pause, and the coordinating session kept it the same day, under the user's rule for the session to decide when sure, over going back to the GPU only or building the design below. Its reason: while the CPU is busy the gate refuses the 35B's batch work anyway, since its group occupies the CPU (item 3), so the pause takes little from Episteme that the gate does not. On strix that day, from 02:28 to 12:15, 587 minutes, the GPU was yielded 302 minutes and the CPU 214, either of them 355: the CPU's verdict added 53 minutes of pause, 9% of the period. That is one morning's observation, not a bound. A day of compiles or encodes would add more. The CPU's `busy_percent` stays at 25.* **A consumer is paused when one of its models has no place, on any host, that can take batch work now.** A consumer names the models it uses. Each host's warden needs the other hosts' device verdicts, which the discovery poll can carry. Rejected: pausing on this host's GPU only, as today; pausing on any device of the host, which would stop Episteme's GPU work when only the CPU is busy.

Defaults the agent chose, open to change:

- On a CPU every process outside InferMux counts, the desktop included. `desktop_processes` exists because the compositor's steady 30-38% of the GPU is not a reason to yield. On the CPU the desktop is the work being protected, and the threshold absorbs its background.
- A model occupying the GPU and the CPU keeps normal CPU weight, and only CPU-device models run in the idle slice. Putting the 27B's threads at idle weight would make the user's own chat crawl whenever the desktop is busy. The warden refusing its batch work is what protects the desktop from it.

## Consequences

- llama-swap's YAML is no longer the file format (0005, 3). Each host generates llama-swap's config from its part: its models, and one group per device.

- Changing which keys are trusted needs a rebuild. That is the point.
- The nixcfg copy carries its signature, so it can start a fresh host.

## Calls the agent made while building, for the user to review

The user, 2026-10-10: "you may drive this to completion on your own. but note down any decisions that would normally be surfaced to me first". Each of these is open to change.

### The format (`internal/placement`)

- **A model file is a llama-swap model entry plus `files:`.** `models/<name>.yaml` holds what a `models.<name>` entry held (`cmd`, `env`, `ttl`, `capabilities`, ...) without the `models:` wrapper, so today's files move over nearly unchanged and llama-swap's own loader checks them. `files:` maps each weight's path to its `sha256` and optional `hf` source (0012's `org/repo/file`). A GGUF named in the command but missing from `files:` is a warning, not an error. InferMux reads and rewrites a model's `cmd`, `env`, `aliases`, `files` and `vram_mb` by name, so a merge key, `<<`, at the top of a model file is written out first, in yaml.v3's order, which is llama-swap's: the file's own keys win, then each source's keys before its own merge, the first source first. An anchor inside the merge key's value is refused, since the written-out file no longer holds the value. The agent's call, after sol's review 15 found a merged `vram_mb` read by neither InferMux nor its whole-number check; refusing every merge key was the simpler alternative. InferMux finds and removes those keys, and a place's settings and flags, by their text, so a key it reads is a plain string, quoted or tagged `!!str` or neither, and it refuses any other: an alias, which yaml.v3 reads as the node it names, a tag but `!!str`, such as `!!binary`, and a key yaml.v3 reads as a number, a bool or null. sol's review 16 had `? *key : 3100`, with `&key vram_mb`, read as `vram_mb` by llama-swap and as `key` by InferMux. The agent's call; reading each key as yaml.v3 decodes it was the alternative, and yaml.v3 does not read a key one way: it compares a merged key with a field by its decoded value, so `1` and `'1'` are two keys there.
- **A model on two devices of one host has two names there.** Its first place on that host, balance before failover, serves the model's own name; any further device serves `<model>@<device>`, unlisted and without aliases. The embedder on strix is `Octen-Embedding-4B.Q8_0` on the GPU and `Octen-Embedding-4B.Q8_0@cpu` on the CPU, and the zbox routes to the second as `strix/Octen-Embedding-4B.Q8_0@cpu`.
- **A model's own lane entry replaces its group's, per lane.** A model in two groups that both have an entry in the same lane is refused, since their order would be a guess.
- **A placement's `flags` match the exact spelling.** A value sets the flag's values, `true` keeps it bare, `false` or null removes it. `-c` does not override `--ctx-size`. The device's flags apply after the placement's, so no override puts a CPU placement's layers on a card.
- **The CPU device's flags replace the ones a command has.** A command with a spelling of `-ngl` or `--device` loses them and gets `--device none -ngl 0`. Any other command, such as the reranker, immich-ml, or a llama.cpp entry that leaves the layers to llama.cpp's default, gets `CUDA_VISIBLE_DEVICES=` alone, which keeps every CUDA build here off the card. The first rule sent the flags to every command with a `--model` ending in `.gguf`, taking it for llama.cpp, and dikt-server, which loads a GGUF through transcribe.cpp, refused them on 2026-10-16 when its speech models got a CPU place. Placement cannot tell llama.cpp by its program, since each host's Nix defines the macro a command starts with. The cost: a llama.cpp command without `-ngl` on a CPU place, built for a backend that ignores `CUDA_VISIBLE_DEVICES` such as Vulkan, could still offload. Neither host has such a build.
- **`concurrent` defaults to false on every device,** so a device runs one model at a time unless the config says otherwise. Each host's part is one llama-swap matrix router, whose sets choose one of each device's models or `together` groups, or all of a concurrent device's, so a model starting on one device never stops another device's (0029).
- **Clouds are offered by every host,** as llama-swap peers, with the key taken from each host's environment through `${env.VAR}`.
- **A model placed nowhere is a warning, not an error.** Removing a model's places is how it is turned off without deleting its file and notes.
- **A host the config does not list runs no model of its own** and still routes to the others.

### Signing and the store (`internal/configstore`, `cmd/infermux-config`)

- **The manifest is JSON with a `parent`,** the hash of the manifest it was edited from. A config whose parent is the one running replaces it quietly; any other later one replaces it as a conflict. Without the parent a host could not tell an edit made apart from a plain update.
- **A tie in signed time goes to the greater host name,** `zbox` over `strix`. Any fixed order would do.
- **A signed time more than 10 minutes ahead of the host's clock is refused.** The later time wins every conflict, so a config stamped a year ahead would beat every edit for a year.
- **An older nixcfg copy at start is ignored, not reported.** The copy lags whenever a Publish has not been committed, so treating it as an edit made apart would raise a warning on most restarts. An older config from another daemon is still a conflict.
- **A public key is its 32 bytes in base64,** one a line in the file Nix writes, with an optional comment after it. The private key file is age's scrypt format holding the seed in base64, so `age -d` opens it by hand too.
- **The daemon keeps the last 20 versions** under `versions/`, besides the current one and both sides of an open conflict.
- **`infermux-config` signs from a terminal:** `keygen`, `sign` (checks the config as a daemon would and refuses to sign one that fails), `verify` and `derive`. The migration needs it before the editor exists, and it stays useful when no browser is at hand.

### The daemon (`infermux_config.go`, the failover lane)

- **The trusted keys are a flag, `-config-trusted-keys <file>`, and setting it turns the one config on.** `-config-state` (default `$STATE_DIRECTORY/config`) and `-config-seed` (nixcfg's signed copy) go with it. Flags rather than environment variables, as the other InferMux settings are flags, and Nix writes them into `ExecStart` where they show.
- **`remote_key_file` in `warden.yaml` is this host's key for the other hosts.** Under the one config, `warden.yaml` refuses `remotes` and `failover_file` and requires `host`, so a host cannot route by two tables at once. The path is used as written, like a remote's `key_file`.
- **The derived file is `<-config-dir>/infermux.yaml`, and InferMux reloads llama-swap itself when it writes one.** The `-config-dir` watcher is not started in this mode. The reload still waits for interactive quiet (0005).
- **At start, llama-swap reloads once it serves.** llama-swap reads `-config-dir` before the warden starts, so a seed or a newer kept version means one reload. A SIGHUP before llama-swap installs its handler would end the process. `http.Server.BaseContext` runs inside `Serve`, after that handler is in place, so the reload hangs on it: no timer, and no edit to `llama-swap.go`.
- **Each host polls the others' `/warden/config/state` every 30 s,** the model lists' period, and fetches only a config signed later than its own. A push is the fast path; the poll catches a host that was down for one.
- **Any key may POST a signed config.** The signature is the authority, so the host key that carries a config between hosts cannot write one. The warden's write guard still applies.
- **A config that some host cannot run is refused at Publish.** `infermux-config sign` and `verify` derive every host's part first, and Publish loads its own host's part with that host's runtimes (decision 11). A host that still meets one it cannot derive, say from a newer InferMux elsewhere, or whose part names a runtime its Nix lacks, refuses it before its store sees it, keeps running the last one, shows it as `rejected` in its state, and does not fetch that version again. The hosts then run different versions until the next Publish.
- **When a host's config is replaced by one edited apart from it, the host pushes the losing version to the others,** so the host that published it learns it lost and both show the warning (decision 6). Dismissing the warning on one host clears it on the others.
- **A balance place at its limit is busy, not refusing.** The request queues there, as 0019's overflow does, and the failover lane is not tried (decision 2). Only when every balance place is down, refusing, or ruled out (`only_if_idle` on a yielded card, `batch_only` for an interactive key) does the request move to the failover lane.
- **A CPU device's servers run as the children of a runner service, `infermux-cpu.service` in the root `idle.slice`, not through `Delegate=` or a transient unit as "Proposed by the agent" said.** `Delegate=` hands over the service's own subtree, which sits under `system.slice`, so no slice there is idle against `user.slice`. A transient scope at the root needs polkit's `manage-units` for the daemon's user. systemd 261 gives polkit the unit's name, so a rule could allow only `infermux-cpu-*.scope`. But a scope's `PIDs` takes any process (`unit_pid_attachable` never compares its owner with the caller), so the daemon could pull root's processes into a scope with limits of its choosing. A template unit started by `systemctl` avoids that, but leaves units running when the daemon dies and puts the servers' output in the journal, out of llama-swap's log. The runner needs no grant. It runs as the daemon's own dynamic user, and its socket lets in only that user. A CPU model's command becomes `infermux-cpu run -socket /run/infermux-cpu/socket -- <command>`. That client relays the server's output to llama-swap, and its connection ending, on llama-swap's stop or its death, stops the server and what the server forked. Without `-cpu-socket` the CPU models run as the daemon's children, and the config's state warns about each one.

### Fetching a missing file (`internal/fetch`)

- **A model whose file is missing stays in llama-swap's file, and a gate answers 503 for it until the file is here.** Leaving it out would mean a llama-swap reload, which stops every model and waits for quiet, each time a download completes, and a request addressed to this host would get llama-swap's "no such model" instead of the reason. The failover handler already moves on from a 503 (decision 8's "skips that placement"). The 503's message names the file, its state, its progress and its source.
- **A file already at its path is the user's own and is not hashed.** Only what comes from another host or Hugging Face is checked, which is the attack the hash is for. Go's SHA-256 read a 5.5 GB GGUF at 1.84 GB/s on strix, so hashing strix's placed weights, about 25 GB, would add some 15 s to each start and each config change. Consequences: a host serves its copy without checking it, and the receiver's check catches a wrong one; a file whose `sha256` changes in the config while its path stays the same is not fetched again. A once-per-file check, cached by size and modification time, would show a local copy that differs from the config. Not built.
- **Other hosts first, in name order, then Hugging Face, one download at a time.** Each source resumes the part file beside the target, `<path>.infermux-part`, whichever source began it; the hash over the whole file decides, and a mismatch deletes it and tries the next source. A file no source gave is tried again after 10 minutes, or at once when a new config arrives. A source that sends nothing for a minute is given up on; the whole file has no time limit.
- **No Hugging Face token in the daemon.** A gated repository answers 401, and the file stays `failed` until the user or the editor's add-model command, which has 0012's token, puts it there.
- **Any key may download a file the running config names,** as any key may read `/warden/*`. The files are published models, and keys.yaml has no field that marks a host's key. Nothing outside some model's `files:` is served, whatever the key.
- **The daemon writes only under `-fetch-dirs`, the module's `signedConfig.fetchDirs`, and through a group, `signedConfig.fetchGroup`.** The module does not change who owns `/srv/models`, which is `alexander:users 755` today. Making it group-writable, as `/srv/models/comfyui` is for `comfyui`, is a host change for the migration (phase 8), in nixcfg. Without the flag a missing file is `unfetchable`, and its model is refused here.
- **A fetched file belongs to the daemon's dynamic user.** systemd derives the UID from the name, so it stays the same in practice, but a dynamic UID is guaranteed only inside the unit's own directories. The files are 0644, and deleting one needs only the directory's group write. If that matters, the fix is a static `infermux` user.
- **The config's state lists each wanted file** with its state, source and bytes done, for the editor's margin later.

### The editor (`internal/muxui/config.go`, `webui/src/routes/Config.svelte`, phase 7)

- **CodeMirror 6, with completion and hover from InferMux's own walker over the schema (`webui/src/lib/yamlschema.ts`).** Not Monaco, and not `codemirror-json-schema`. Most of what is worth completing comes from the draft itself rather than the schema: `host/device` places, model names in a group, the unplaced models and groups as a lane's keys, the GGUFs on this host. The walker reads the lines above the cursor by indentation, so it still works on a draft that does not parse.
- **The schema is generated from the Go types (`internal/placement/schema.go`), with llama-swap's model entry embedded from upstream's `config-schema.json`.** `TestUpstreamModelSchema` fails when the embedded copy differs from upstream's after a merge, and `-update` rewrites it. Two annotations say what to complete: `x-complete` for a value and `x-complete-keys` for a mapping's keys, each one of `place`, `device`, `model`, `lane` or `gguf`.
- **The check is the daemons' own loader,** `placement.Parse` and every host's derivation, run by the UI as the draft is typed. Only YAML errors and a few decoding errors carry a line. A place on a missing device or an unknown model in a lane has no file and no line, so it shows in the Check panel and not in the gutter. Line numbers for those would mean the loader keeping each `yaml.Node`'s line through `Place`. Not built.
- **The editor's YAML parser is stricter than the daemons'.** `embedders: [alpha]# a note` is an error in the editor (a comment needs a space before it) and accepted by yaml.v3. The mark is then a false alarm; Publish follows the loader.
- **The draft lives in the browser's localStorage,** with the hash of the version it was made from. A draft with no edits follows the running version. One draft per browser, not per host or user.
- **Publish refuses a draft made from an older version with 409, and shows the two side by side.** "Build on the running version" makes the running version the draft's base and keeps the draft's text, so the draft wins wherever both changed; the comparison's arrows take the other side's changes into the draft first. "Publish over it" signs with the old base as parent, so every host records a conflict (decision 6) rather than a quiet replacement.
- **nixcfg's copy is written only once the daemon runs the version** (`applied`, `replaced` or `same`). On `old` or `lost`, when a later version won meanwhile, the copy is left as it was and the UI says so. "Copy the running version here" writes the running version into nixcfg on request, never by itself.
- **The model form, Peers, Routing and Downloads are hidden under the one config, not removed,** and their write routes answer that the UI edits the one config. Decision 9 has the editor replace them. They go in phase 8 with the models directory, once both hosts run the one config.
- **Add model takes a GGUF on this host, one on Hugging Face, or nothing.** The UI hashes a local file, only under `-gguf-dirs`. For Hugging Face it takes the LFS `X-Linked-Etag` and refuses a file that is not in LFS, which has no SHA-256 there. A Hugging Face file's path is `<first gguf dir>/<file name>`, not 0012's `org/repo/file` tree, so two repos' files with one name would collide. The command is copied from the first model whose command starts with the same runtime, its `--model` replaced and its other `.gguf` flags (mmproj, draft) dropped, with a comment that says so.
- **The KV-kernel warning is a warning on the cache type flag in a model's `cmd`.** A placement's `flags` can change the pair per device; those are not checked.
- **`${` in a model file offers the base config's macros, the runtimes, then llama-swap's `PORT` and `MODEL_ID`.** Not `${env.*}`.
- **The frontend's tests run with `bun test` (`webui/test/`), with no new npm dependency.** bun is a check input of the webui derivation, so `nix build` runs them.
- **The Config tab is loaded on first use.** The main bundle stays at 109 kB. The Config chunk, CodeMirror included, is 577 kB, and Vite's chunk size warning remains.
- **The module's `ui.configKey` is the encrypted key; under the one config the UI edits `signedConfig.seed`,** the directory the daemon starts from, and gets no `-models-dir`.
- **`e2e/config.py` runs the tab against a daemon with a signed config,** and both e2e base configs set `startPort: 15800`: the host's own InferMux had a model server on 5802, which the e2e daemon's third model was given.

### The warden on every device (`internal/warden/cpu.go`, `internal/warden/devices.go`)

- **A host has two measured devices: the GPU at NVML index 0, and the CPU.** A model placed on a card at another CUDA index is on no measured device, and the config's state warns about it. No host has two cards today. Measuring several would mean one GPU verdict per index; NVML already lists them.
- **Outside the one config the warden is what it was.** Every local model is on the GPU, the CPU is not read, and the refusals and unloads are the old ones.
- **A local model the placement does not name is on both devices,** and either device's yield refuses its batch work. The derivation names every local model, so this is only a model llama-swap knows from somewhere else.
- **Free VRAM is read whenever no GPU model runs** (AGENTS.md's rule, reworded). A CPU model's server runs with `CUDA_VISIBLE_DEVICES=` and holds no VRAM, so it no longer hides a full card.
- **The CPU's percent is of every online core,** counted from the `cpuN` lines of `/proc/stat`. 25% on strix's 24 threads is 6 busy threads. It is the sum of the readings within `window_seconds`, so the window slides instead of restarting.
- **Ours is InferMux's own unit, `our_units`, and the CPU runner's unit.** The daemon reads the runner's unit through the runner's socket: SO_PEERCRED gives the pid, and `/proc/<pid>/cgroup` the unit. No new flag or key. A runner that does not answer yet is asked again every 5 s. The cgroup tree is walked for those names once a minute and whenever one cannot be read, and a cgroup inside another of ours is counted once.
- **The busiest processes come from `/proc/<pid>/stat`:** the top three by CPU time since the last reading, grouped by name, InferMux's units left out. Reading 860 processes took 8 ms on strix. They name the reason on the Status card and decide nothing; the decision is the cgroup sum.
- **The checks run in the order RAM, priority process, load,** so when RAM is short the reason shown is the one that unloads.
- **Defaults: 25% busy, a 30 s window, 300 s of resume quiet, 4096 MB of available RAM.** 25% is the GPU's number, and three to six times strix's measured background of 4-8%. The RAM floor has one measurement behind it and is otherwise a guess. Unloading the 4B embedder on CPU freed 2.8 GB of anonymous memory; the other 4.2 GB was file pages, which MemAvailable already counted. The floor has to sit above what the desktop needs to keep out of swap, and 4 GB is that on a 96 GB host.
- **A CPU yield on load or for a priority process refuses and cancels batch work on the CPU's models, and unloads nothing.** RAM under the floor owes one unload of the CPU's models, paid after `interactive_recent_seconds` of quiet on those models only. A chat on the GPU does not hold back the CPU's unload. Each fall under the floor owes another one, including a fall during the resume quiet.
- **A CPU priority process does not skip the interactive wait,** as a GPU one does (0017). It does not unload anything, so there is no wait to skip.
- **A refusal names the device that refused:** `gpu_yielded`, as before, or `cpu_yielded`, with that device's reason and its own `resume_quiet_seconds` as Retry-After. A model on both devices is refused by the first of them that is yielded.
- **A batch request cancelled by hand now answers type `cancelled`, "batch request cancelled by hand",** where it used to say `gpu_yielded` and give the GPU's reason, true or not. Retry-After stays the GPU's `resume_quiet_seconds`. Episteme honours Retry-After, and 0 would have sent the work straight back. No consumer matches on the type.
- **Unload all, Forgive owed unload and Cancel batch requests act on both devices.** Pause and Resume by hand stay the GPU's.
- **Consumers hear the GPU's verdict only.** Decision 4's push to consumers was replaced by 0023 the same day, so the CPU was never added to it.
- **Overflow (0021) asks the devices of the model.** An `only_if_idle` place refuses while any device its model is on is yielded. The one model at a time on a card counts only models on the GPU, so a CPU model is never GPU work there.
- **Disabling the warden drops the CPU's verdict too,** and its batch work goes through.
- **The UI:** the Status page has a CPU card under the GPU's, and the Models card lists each model's devices or "unmeasured". The Warden settings have a CPU section with the four numbers and the priority processes. `e2e/config.py` checks the card and the placement the daemon derives; `e2e/run.py` checks that the CPU's numbers save.
